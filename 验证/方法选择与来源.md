# 方法选择与来源

检索日期：2026-09-19。此项目是电商订单经营核对，生命科学期刊的分析工作流不适用，因此参考 2025 年平台交易接口规范、当前平台财务口径说明以及金额计算官方文档。这里的比较是本项目的工程选择，不声称完成了全行业方法调查。

| 常见手工做法 | 本项目采用的做法 | 原因 |
|---|---|---|
| 按订单做一次查找，取首条退款 | 按唯一退款流水编号校验，再汇总多笔成功退款 | 一单可能多次退款；重复与多笔合法交易不同 |
| 有退款单就扣减 | 区分成功、处理中、失败 | 退款对象存在不代表资金处理已完成 |
| 空成本默认为 0，删除重复行 | 隔离问题订单并保留全部原始记录 | 避免制造看似完整的利润 |
| 使用二进制浮点加减或人工估算 | Decimal 解析，整数分运算 | 明确金额精度，不自动舍入 |
| 只保留最后一次工作表 | 原始文件、哈希、行号、规则参数和运行快照 | 便于复核同一结果的来源与计算过程 |

推荐本项目继续使用固定四表、订单批次归集和确定性代码。只有收到首家商家的明确原始导出与字段口径后，再添加一个经过测试的专用转换器；本版未实现平台 API、通用自动映射或会计记账规则。

参考来源：

- Shopify 2025-10 Refund：退款与订单关联，实际资金状态在交易记录中，不能只看退款对象存在。https://shopify.dev/docs/api/admin-graphql/2025-10/objects/Refund
- Shopify 财务报表帮助：销售、退款与支付报表具有不同含义，须明确口径。https://help.shopify.com/en/manual/reports-and-analytics/shopify-reports/report-types/default-reports/finances-report
- Python Decimal 官方文档：十进制精确计算与会计相等性约束。https://docs.python.org/3/library/decimal.html

这些来源用于选择工程规则，不是法律、税务或审计鉴证依据。
