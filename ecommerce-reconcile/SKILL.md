# 电商经营核对 MVP

先读 [输入格式与口径](references/输入格式与口径.md)。只支持其中的固定四表 v1，币种 CNY。平台原生导出若不匹配，输出字段差异或空白模板，不自行猜测映射、净收款定义、金额和成本。

## 操作

1. 将用户提供的四个文件原样保存到独立输入目录，使用规定文件名。不要在原文件上编辑或另存覆盖。若原名不同，保存原名备份，并另外记录来源文件名、角色、目标名和 SHA-256 的映射。
2. 确认本次核对截止日及同一批订单的数据覆盖范围；未提供截止日时可使用当前当地日期并明示。退款无记录表示已提供范围内无退款，不证明商家没有漏交文件。
3. 使用 `scripts/reconcile.py` 计算。不得用语言模型、心算或 Excel 公式替换金额引擎；不自动修剪编号、不去重、不补零、不舍入、不分摊费用。
4. 在新输出目录交付 `经营利润报表.xlsx`、`异常清单.json`、`计算说明.md`、`审计记录.json`、`原始数据/` 和 `交付校验.json`。检查 `完成标记.txt`，没有标记表示导出未完成。
5. 从审计 JSON 引用金额、行号和状态解释结果。若 `complete=false`，明确“小计不能作为全店利润”，列出需商家按凭证补正的字段；不要承诺最终利润。提醒类问题仍按原值计算。
6. 商家提供确认后的新副本后，在另一个新输出目录重跑。保留前后两次记录，不直接修改报表。

## 执行

运行需要 Python 3.10+、openpyxl，以及 Node.js 与 `@oai/artifact-tool`。在 Codex 中优先调用 `load_workspace_dependencies` 获取当前捆绑路径。在 Skill 所在目录或父目录建立指向捆绑 node_modules 的目录联接，避免复制依赖。金额引擎仅用 Python 标准库；openpyxl 仅读取输入，Artifact Tool 仅负责 Excel 展示。

```powershell
& '<python路径>' -X utf8 '<skill路径>/scripts/reconcile.py' --input '<四表目录>' --output '<新输出目录>' --as-of 2026-09-19
```

退出码 0：已上传数据通过规则校验；2：成功生成了含阻断问题的报表；1：执行或导出失败。不能把退出码 2 当作没有产物，也不能把 0 解读成全部交易已上传或报表已获会计审计。

随交付目录附有 `run.ps1`，可在本机解析捆绑依赖。演示与 50 组测试放在 Skill 父目录，不是商家真实数据。`test_reconcile.py` 默认复核已有模拟输入及两份演示输出；`--prepare` 会准备模拟文件生成清单，仅用于开发测试。

## 结果口径

订单经营贡献 = 实收 - 成功退款 - 平台费用 - 商品成本 - 履约成本 + 明确提供的成本冲回。

结果为本批次订单截至核对日已提供流水的快照，未做税费、租金、人工、广告或库存计价，不是自然月权责利润、银行到账核对或审计鉴证。Excel 改值不会重新计算；必须修正来源副本后重新运行。
